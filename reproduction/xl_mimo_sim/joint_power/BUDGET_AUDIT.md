# 搜索预算与功率建模审计（2026-09-22）

这是实现审计与后续比较规范，不是RL已获胜的实验结果。没有改动冻结的phase1/2/3训练或测试。

## 1. 当前算法究竟联合控制什么

RL从排序前缀1–16及保持命令共17项中选择子阵命令；给定实际活动子阵后，所有方法都使用同一个干扰耦合最小功率求解器。
这属于“学习离散激活＋解析功率控制”，不是网络直接输出连续功率，也不是在全部2^16个子阵组合上学习。
如果正文采用此实现，必须写明上述分解，不能把共同功率优化收益全部归因于RL。

固定RZF波束方向时，满足速率的功率约束为 p >= Fp+u。若非负干扰矩阵谱半径rho(F)<1，
其分量最小解为 p*=(I-F)^(-1)u，随后检查总功率上限。超过上限时进入共同服务保持回退。
该解析求解已消除大量连续动作搜索，不存在“加入功率后搜索必然难以完成”的依据。

## 2. 旧粗搜索没有真正减少主要候选计算

`Environment.candidates()`先计算17个候选各8时隙的RZF增益和功率，再由`search_action(stride=3)`筛选7项。
因此旧粗搜索与完整搜索均已支付136个候选-时隙的主要求解工作；步长只改变候选集。
这些旧结果保留，但不能标成等计算预算实验或用于证明实际在线加速。

新隔离核`budgeted.evaluate()`先选数量网格，再计算其物理预测；步长3实际只评估7×8=56个候选-时隙。
步长1仍是17×8=136。全激活与保持命令始终保留，信道预测、观测权限、速率阈值、功率和不可行回退不变。
单位测试检查所有候选数值、所选动作及实际传入物理核的批量形状，不给搜索加噪声或额外能耗。

**当前PDS-RL仍要计算全部17项的预测特征，之后才做网络推理。**
所以它不能仅凭一个网络前向就宣称比这项56候选-时隙搜索省计算。
正式等时延比较必须计入预测、特征、校准、网络/搜索以及共同功率控制；训练时间另列。
上面的计数不是FLOPs、毫秒或实测CPU耗电，也没有把同时训练时的计时当作部署时延。

训练完成后，在本机CPU、Torch单线程、8个已完成共同观测更新的状态上，分别暖机并随机交错重复计时；
每种方法400次。包括各自预测、特征、求解和网络选动作，不含共同观测更新、实际逐时隙功率执行及训练：

| 选动作实现 | 中位数 / ms | 95%分位 / ms |
|---|---:|---:|
| 原PRS | 0.664 | 0.772 |
| 联合完整数量搜索 | 2.377 | 2.799 |
| 真正子集计算的联合粗搜索 | 1.645 | 1.925 |
| 当前分支训练RL，含全部预测特征 | 3.559 | 4.121 |

这次有限本机计时反而显示当前RL较慢，不能用“搜索太慢”作为故意减少其预算的依据。
它不是所有硬件/状态上的速度定理，更不是完整无线系统时延或处理器电能测量。
40项候选子集数值等价检查全部通过。脚本`benchmark_budgeted.py`，原始计时与平台信息在
`../results/joint_decision_budget_checks_20260922`；训练期间没有进行这项正式计时。

## 3. 当前功耗权重对节能空间的约束

现配置每回合140×0.05=7秒，总发射功率上限1.2W，恒定功放效率0.4。
即使把发射功率全降为零，能够省掉的功放能量也至多为7×1.2/0.4=21J。
这只是数学上限，零发射不能保持业务，不代表可实现节能。
全激活固定功率基准为305.653376J，因此这个理想上限只有其约6.87%。
固定相同开关轨迹时，功率降低不会同时消除电路、恢复或导频消耗。

另一个可核算的局部界限：忽略过渡过程，在同样持续时间里多维持一个已准备子阵，
活动相对休眠的电路差1.95W，处理差0.001536W，当前每时隙观测模型的导频差0.04W，
合计约1.991536W。仅从即时能耗看，需要降低至少0.7966144W发射功率才能抵消。
两个额外子阵的稳态成本约3.983W，已超过全系统最多3W的功放输入功率。
这些是在当前恒效率/导频假设下的局部能量界限，不是无视可靠性和未来恢复收益的关断规则；
不能用来排除高需求时为满足速率而多开子阵，也不能当作其他硬件的普适定律。

上一轮名义场景，PRS+功率为122.678J，其中功放3.374J；RL为137.610J，其中功放2.482J。
RL已少用约0.893J功放能量，却多用约12.161J电路/处理和3.501J切换能量。
这解释了为什么仅继续降低发射功率不能抵消当前额外子阵/恢复成本，不能据此断言RL永远无优势。

物理参数是研究假设，不是本项目实际基站测量结果。不得为了扩大RL收益单独放大搜索功耗、
改变某一方法的功放效率，或声称当前常数已经得到运营商标定。

## 4. 文献对模型选择的启示与边界

Peschiera等研究了基于测量功耗模型的时间、空间和功率资源联合优化，指出硬件是否支持时间域休眠会改变最佳节能策略；
其部分条件下少开天线的简单策略接近最优。参见原作者全文
[On Optimizing Time-, Space- and Power-Domain Energy-Saving Techniques for Sub-6 GHz Base Stations](https://arxiv.org/html/2505.15445v1)。
其sub-6GHz、统计ZF、平均速率及非恒定功放效率模型与本项目14GHz、RZF、逐时隙业务和恢复延迟不同。
它支持“先核查物理功耗再选择算法”的研究思路，不支持直接移植其数值、宣称本项目已实测标定，或承诺RL必胜。

## 5. 后续可支持的结论

| 主张 | 所需证据 | 当前状态 |
|---|---|---|
| 粗搜索确实少算候选 | 主要物理核输入批量与数值等价 | 新核与测试可检查；旧结果不改标签 |
| RL在同等在线预算更节能 | 同硬件全流程时间、相同可靠性、新独立测试 | 未完成；当前RL有全候选特征成本 |
| 联合控制的额外收益来自学习 | 相同功率控制能力的强搜索及非学习对照 | 正在phase3筛查，不预设结论 |
| 当前物理模型代表真实基站 | 可追溯器件/测量参数及适配场景验证 | 尚无；不得靠调差对照替代 |

不因完整搜索获胜而删除它，也不把搜索空间内最优误称为全时域全组合的全局最优。
后续可以研究受限计算条件，但应先固定合理预算，再报告整条能耗—可靠性—计算量关系。

## 6. 为什么不能预先规定RL一定胜出

若完整搜索和粗搜索对同一状态使用相同的准确代价J，且粗搜索的可行动作集合A_b包含在A中，
则在两者都存在可行动作时，min_{a∈A}J(a) <= min_{a∈A_b}J(a)。
RL从相同A中输出一个动作，也不能在这个准确的同一优化目标上低于真正的最小值。
本项目的完整数量搜索并不是这个理想全时域优化器：它只评估固定命令的有限预测范围，且预测存在误差。
RL可能获益的空间是学习之后还会调整命令的长期代价，而不是违反上述最小值关系。

同理，粗搜索较差的预测目标值并不保证真实闭环能量也较差：有限候选可能偶然更保守，
避免预测错误引起的不达标或切换。这也是必须同时实测可靠性、能量与算力，而不能只由步长推导“RL更好”的原因。

目前训练的e+λc是能量与不达标的惩罚目标，λ通过验证选取；它不是已证明满足逐时隙安全约束的控制器。
5%门限是预先规定的评价筛查条件，不能写成硬性可靠性保证。
