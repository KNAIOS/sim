# 搜索策略模仿诊断：完成，但未达到进入 RL 微调的门槛

本报告是作者侧的方法研发记录，不是新的投稿结果或 RL 优势证明。
冻结方案为 `DEMONSTRATION_PLAN.md`，原始数据目录为
`../results/major_revision_20260920_demonstration`。主稿原方法未替换。

Detected axes: task_type=communications; evidence_type=baseline, ablation,

stage=audit.

## 1. 为什么做这一步

此前共同 1–16 子阵动作范围内，从零训练的 DQN 在低负载下仍开启过多子阵。
因此先检查一个更基础的问题：同一输入和网络能否学会因果预测搜索的决策？
如果连这个初始化诊断都未通过，就不能默认继续增加 RL 训练会产生优势。

这是监督模仿及有限次数的数据聚合，不是新 RL 算法；输出为动作分类分数，
不是经过 TD 训练的 Q 值。即使模仿成功，也不等于超过搜索或证明通信创新。

| 待验证主张 | 所需证据 | 本轮证据 | 结论 / 审稿风险 |
|---|---|---|---|
| 当前输入/网络可以作为可靠的搜索模仿初始化 | 未参与训练的动作一致率及闭环能耗、速率不达标比例 | 两种子、三个固定训练阶段、独立验证轨迹 | 两种子均未通过预定门槛；不得直接进入微调并宣传改善 |
| 接触自身产生的状态有帮助 | 初始模仿与固定两轮聚合的对照 | 三个端点全部保留，未按开发集选模 | 个别指标变化，不是稳定改善，也不是 RL 贡献 |
| RL 在可靠性约束下比强搜索更省电 | 冻结的新 RL 与强搜索在独立确认集上的比较 | 本轮没有 RL 微调；此前候选也未通过 | R1 仍未解决，属核心风险 |

## 2. 完成的工作与公平性

1. 先增强搜索教师：在同一 982000000 校准流上，从最小计数 1 或 4 及六个
   预测裕量中按可行性优先选择。允许 1–16 个子阵不应排除原有的最少 4 个
   子阵策略。选定低/常规/高场景的设置分别为 (1,1.04)、(1,1.08)、(4,1.04)。
   共 432 条搜索校准记录；教师选择发生在查看后续开发结果之前。
2. 生成 96 条训练轨迹的 3360 个因果教师标签，另有 36 条验证轨迹的
   1260 个标签。训练和验证轨迹流不同，验证标签没有加入训练。
3. 两个网络种子均保持 235→64→64→16 结构，先训练 100 轮；然后固定进行
   两轮自身状态聚合，每轮每个种子新增 36 条轨迹、1260 个标签，再训练
   50 轮。因此每个种子最后使用 5880 个训练标签，累计 200 个训练轮次。
   此处训练轮次是遍历数据的 epoch，不是新的物理仿真轨迹数量。
4. 按验证集逐场景中断超额、再按能耗选端点。种子 11 选聚合第一轮，
   种子 22 选聚合第二轮。不是按最高动作准确率或开发结果挑选。
5. 选择锁定后，在新的 993000000 流每场景 16 条轨迹上评估初始模仿、
   选定模仿、搜索教师和全阵列。共 288 条策略评估记录，但只有 48 条
   外生开发轨迹；不能把共享轨迹、多个策略和多个种子视为独立样本。

三种场景分别是速度 0.5/2/3 m/s 与负载系数 0.85/1/1.15 的联合设置，
不是分别控制速度和负载的单因素实验。物理信道、功率、导频、恢复时延和
切换费用均保持不变。所有策略仍按同一子阵排名选择前若干个子阵。

## 3. 初始化门槛为什么没通过

预先设定的门槛同时要求：验证动作一致率至少 90%；每个场景的平均能耗
不超过教师的 110%；每个场景的速率不达标比例至多高出教师 1 个百分点。
两个种子均须通过。这个门槛是研发停止规则，不是理论上的 RL 必要条件，
也不是统计可靠性认证。

| 种子 / 选定端点 | 训练动作一致率 | 验证动作一致率 | 验证平均计数绝对误差 | 门槛 |
|---|---:|---:|---:|---|
| 11 / 聚合第一轮 | 73.94% | 56.11% | 1.014 个子阵 | 未通过 |
| 22 / 聚合第二轮 | 72.64% | 55.56% | 1.048 个子阵 | 未通过 |

种子 11 在高场景验证能耗比教师高 11.28%，速率不达标比例高 3.17 个百分点；
种子 22 虽在该场景能耗低 5.32%，不达标比例却高 5.60 个百分点。因此问题
不只是严格的 90% 分类门槛：实际闭环约束也没有达到。

训练一致率同样没有接近 100%，且验证更低。现有证据只能说明这套固定的
数据、输入、网络及优化流程没有学好；不能据此单独断言是训练太短、网络
太小、输入不充分或过拟合，更不能把其中任何一种猜测写成已证实原因。
若要主张输入丢失了决策信息，需要额外的可辨识性反例或受控特征消融。

## 4. 新开发集的实际节能—可靠性结果

每次仿真为 140 个 50-ms 时隙，即 7 s。能耗包含运行、切换和导频能量，
不是硬件实测值。速率不达标比例统计用户—时隙上的需求未满足事件，不应
表述为整站掉线概率。模仿结果平均两个训练种子；搜索和全阵列不依赖网络种子。

| 场景 | 搜索能耗 / 不达标比例 | 初始模仿能耗 / 不达标比例 | 选定模仿能耗 / 不达标比例 | 全阵列不达标比例 |
|---|---|---|---|---|
| 低 | 107.11 J / 2.43% | 105.86 J / 6.02% | 106.67 J / 4.87% | 0.00% |
| 常规 | 130.64 J / 3.88% | 127.23 J / 6.62% | 133.85 J / 5.89% | 0.00% |
| 高 | 185.41 J / 3.08% | 200.14 J / 6.58% | 195.18 J / 6.85% | 0.40% |

全阵列每种场景均为 305.65 J。相对全阵列节能，不等于相对搜索有学习收益。

| 场景 | 选定模仿 − 搜索：能耗差及 95% 区间 | 不达标比例差及 95% 区间（百分点） |
|---|---|---|
| 低 | −0.43 J [−1.77, 0.81] | +2.45 [0.20, 5.65] |
| 常规 | +3.21 J [−7.76, 13.09] | +2.01 [0.07, 4.12] |
| 高 | +9.77 J [−16.29, 39.46] | +3.76 [0.19, 6.58] |

区间来自 4000 次保持轨迹配对、交叉重采样种子与轨迹的 bootstrap；仅有
两个训练种子，训练随机性的估计很有限。这是开发诊断，不能包装成大量
训练尝试后的独立确认，也没有进行多重比较校正。低场景的微小能耗差区间
跨零，并伴随更差的可靠性，不能据此称为优于搜索。

本轮高场景全阵列不达标比例 0.40%，与前一批轨迹不同。禁止跨数据流把
此前 5.34% 与这里 0.40% 的差异归因于算法进步；必须比较同表匹配轨迹。

## 5. 检查点恢复与复核

两个训练进程均已完成所有阶段和验证，随后严格加载检查点时因 NumPy 标量
元数据失败。没有重新训练或重新选择模型。`demonstration_recovery.py`
仅对本地生成、已核查来源的检查点使用受限构造器白名单，将标量转为 Python
原生类型；保留 `weights_only=True`，不使用任意 pickle 反序列化。

原始检查点完整保留。`portable_checkpoints/CONVERSION.json` 记录原文件与
转换副本的 SHA-256，并验证所有网络权重逐张量相等。评估使用严格加载的
转换副本。`demonstration_report.py` 又独立重算选模端点、动作一致率和全部
门槛，核验来源哈希、能耗加总、288 条记录唯一键及恢复凭据。结果见
`audit.json`、`imitation_choices.json`、`validation_summary.csv`、`class_accuracy.csv`、
`summary.csv` 和 `paired.csv`。

本轮累计回归测试 85 项通过：64 项 major_revision、21 项原有测试。工作
使用项目已有 venv，无依赖安装或系统环境更改。训练和评估进程均已退出。

## 6. 对返修的实际影响

- R1 仍未解决。不得把模仿标成 RL，不得把初始模仿低能耗但违反可靠性的
  点挑出来，也不得复用原模型的计时/标准信道结果证明这个新网络。
- R2 和 R3 已有的是原稿冻结模型的敏感性与标准信道迁移证据；本轮不改变
  它们的适用范围。没有新模型晋级，所以不重复运行新模型的全套验证。
- 本轮不增加训练轮数、聚合次数或新奖励权重。失败门槛按原方案执行。
- 继续整稿需要作者确定：保留当前设计并收窄为有明确限制的节能控制及
  计算—性能折中，或接受核心方法重构及新的有界研发。前者不保证审稿人
  接受；后者不能预先保证 RL 获胜。未经确认不把收窄后的文章视为目标完成。

后续作者已明确选择第二条：核心方法重构及有界验证。新方案独立记录于
`CORE_REBUILD_PLAN.md`，不是继续微调本诊断的失败模型，也不改本轮停止规则。
