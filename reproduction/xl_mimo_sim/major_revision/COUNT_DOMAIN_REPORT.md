# 四子阵下限不是当前物理模型的必然要求

## 新确认的限制

原控制器与 PRS 都把命令数量限制在 4–16，代码来自 `K+1`，K=3。但
当前 `XLSystem.achievable_rates` 是按所有活动天线构造全数字 RZF；每个
子阵有 Ns=8 根天线。信道矩阵的列数是 M×Ns，不是 M。

因此，从三用户信道的满行秩条件只能得到 M×Ns≥K 这一必要条件，不能
推出 M≥K+1=4。一个子阵的 8 个独立数字分支已经可能提供三个空间维度。
新测试构造一个满行秩的 3×8 信道，在现有速率函数、带宽、噪声和功率下，
仅一个子阵即能让三个用户都超过 560 Mbit/s。这只是否定“必需四子阵”
的反例；不是说真实轨迹、任何 CSI 或任意用户位置都只需一个子阵。

若硬件原意是每个子阵只有一个共享 RF 链，则必须另建受约束的混合预编码
模型，不能既用 M×Ns 个自由数字权重计算速率，又把 M 当成数字空间维数。
本轮未擅自改变硬件架构或物理模型。原四子阵下限应明确称为控制域限制。

## 限制是否影响实际节能空间

按 `COUNT_DOMAIN_PLAN.md`，只比较同一因果 PRS 的两个搜索域：4–16 和
1–16。预测器、原验证裕量 1/1/1.04、真实需求、恢复时延及能耗均相同。
每场景取最前四条已有开发轨迹；4–16 重放逐项复现存档，所有结果保留。

| 场景 | 搜索 4–16：J / 中断 % | 搜索 1–16：J / 中断 % | 新域选择不足四个的决策数 / 140 |
|---|---:|---:|---:|
| 0.5 m/s / 0.85 | 139.121 / 0.119 | 102.184 / 3.631 | 135 |
| 2 m/s / 1.00 | 144.786 / 4.167 | 123.274 / 14.881 | 105 |
| 3 m/s / 1.15 | 195.150 / 3.095 | 185.852 / 6.310 | 35 |

低负载能量均值下降约 26.55%，但中断率升高；名义及高负载明显超出 5%
目标。没有给新搜索域重新校准阈值，所以这些数据用于诊断，不构成最终
公平调优后的算法比较。四条轨迹的均值达标也不意味着可靠性获得认证。

这一结果表明：四子阵下限确实屏蔽了一部分可省电的选择；然而直接放宽
下限会暴露可靠性问题。它没有证明 RL 解决了这些问题，更不能把 26.55%
写成学习收益。简单降低下限也不是新的通信算法创新。

## 对当前返修的实际影响

1. 已在 Section III-C 黄色说明四子阵下限是额外控制限制。原图表仍然
   描述该限制下的原算法，没有用新域的数值暗中替换。
2. 后续要验证充分的节能决策，必须给 RL 和强非学习对照共同的可选数量
   域，并重新在验证集上确定可靠性设置。不能只给 RL 开放 1–3 子阵。
3. 原网络的 13 个计数输出和相关前缀速率特征都对应 4–16；不能通过
   更换动作标签就把旧检查点说成在 1–16 上训练过。若修正主方法，需
   真正重新训练，随后重做相应的独立验证、敏感性和标准信道评估。
4. 关于同数量保留/交换动作，目前只有弱诊断信号，不能一并包装成已
   验证的创新。优先修正并核验动作域与可靠性问题，才有依据安排后续训练。

原问题“RL 是否在共同可靠性约束下优于强搜索”仍未解决，整篇 major
revision 仍未完成。这个发现改变了下一步该修什么，不保证新训练会获胜。
